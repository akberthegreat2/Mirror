# Mirror Archive WARC

`mirror-archive-warc` is the reference WARC provider for the
[`mirror-archive`](../mirror_archive/README.md) capability.

## Install

```bash
pip install mirror-core mirror-archive mirror-archive-warc
```

The provider loads `warcio` lazily during `setup()`. Importing the package does
not open files or create directories.

## Configuration

```yaml
components:
  archive:
    provider: warc

component_settings:
  archive:
    warc:
      output_dir: ./data/archive
      compress: true
      max_file_bytes: 536870912
      max_records: 100000
```

## Runtime contract

- `Application` owns provider setup and teardown.
- `setup()` and `teardown()` are idempotent.
- `archive()` never starts the provider implicitly.
- Records are written as WARC `resource` records.
- Required WARC headers are generated by `warcio`; Mirror supplies the payload
  digest, resource reference, media type, and sanitized metadata.
- Writes are serialized with an async lock.
- Blocking WARC/file operations run in a worker thread.
- Segments rotate before a write would exceed `max_file_bytes`, or after
  `max_records` records.
- Provider/library failures are translated to `ArchiveError` and preserve the
  original exception as `__cause__`.

`ArchiveResult.size` is the uncompressed payload size, not the final compressed
segment size.

## Testing

The package uses deterministic writer doubles for lifecycle, record construction,
metadata sanitization, rotation, concurrency, and error-translation tests. This
keeps the contract suite independent of the host environment. Release CI should
also run an integration test with the real `warcio` dependency installed.
